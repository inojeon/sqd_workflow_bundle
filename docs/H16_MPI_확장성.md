# H₁₆ 32큐비트: STEP 4 배치 병렬의 MPI 확장성 측정

> **실행일:** 2026-10-12~13. **목적:** SQD를 워크플로우로 옮겼을 때 고전 단계(STEP 4)에서 MPI rank 수를 늘리면 실제로 빨라지는 문제를 하나 정해 수치로 보인다. **문제:** 수소 사슬 H₁₆(1.5 Å 간격, STO-6G), 궤도 16·전자 (8,8) 반 채움 = 32큐비트. **한 줄 요약:** 같은 32코어에서 단일 프로세스(스레드)는 1코어 대비 16.6배, MPI 배치 병렬은 23배. 결과 에너지는 모든 구성에서 동일. (D=10⁷·2노드 64 rank 결과는 §5에 추가 예정)

## 1. 이 문제를 고른 이유와 한계

앞선 시험([최대 규모 H₁₈](최대규모_H18_36큐비트.md))에서 양자 쪽을 36큐비트까지 키우면 에뮬레이터 실행이 몇 시간이 걸리고 결과 불일치까지 생겨 본래 목적(고전 단계의 MPI 확장성)과 멀어졌다. 고전 쪽 일의 크기 D는 큐비트 수가 아니라 샘플에 나온 서로 다른 스핀 문자열 수가 정하므로([쉽게 읽는 설명](쉽게_읽는_SQD_고전계산.md), [D가 자라는 법](D가_자라는_법.html)), 큐비트는 32로 낮추고 D는 설정으로 키웠다.

| 항목 | 값 |
| --- | --- |
| 분자 | H₁₆ 직선 사슬, 원자 간격 1.5 Å(늘린 사슬 = 강상관, 넓은 분포), STO-6G |
| 활성 공간 | 궤도 16, 전자 (8,8), 32큐비트, FCI 차원 12,870² = 165,636,900 |
| 기준 에너지 | **FCI −8.061179 Ha**(32코어 22분), CCSD −8.044566(수렴 안 됨), RHF −7.422104 |
| 회로 | LUCJ 2회(CCSD 진폭 초기화), ISA 게이트 780개, 깊이 57 |
| STEP 3 | ffsim 정확 샘플러, shot 50만, 31초 |

**이 문제는 고전으로도 풀린다.** FCI 공간 1.66×10⁸은 1노드에서 22분이면 완전 대각화되고, 1차원 사슬은 DMRG로 몇 분이면 끝난다. 에뮬레이터로 돌릴 수 있는 36큐비트 이하는 모두 이 범위다. 따라서 이 측정은 "양자가 필요한 문제"가 아니라 **"SQD 고전 커널(배치별 대각화)이 MPI로 얼마나 나뉘는가"** 를 재는 것이고, 워크플로우 변환의 검증 대상도 그 커널이다.

## 2. 샘플 다양성과 D

STEP 3의 shot 50만 개에서 서로 다른 스핀 문자열 수(가능한 12,870 중):

| shot 수 | ↑ 문자열 | ↓ 문자열 | ↑∪↓ |
| ---: | ---: | ---: | ---: |
| 10,000 | 1,091 | 1,101 | 1,496 |
| 50,000 | 2,252 | 2,247 | 2,915 |
| 500,000 | 4,907 | 4,893 | 5,882 |

배치당 샘플 5만 개면 목록 길이 약 2,900이라 D는 8×10⁶까지 자연스럽게 커지고, 이월로 더 자란다. 그래서 `max_dim`(스핀당 목록 상한)을 1,000(D=10⁶)과 3,162(D=10⁷) 두 단계로 두었다. D=10⁸은 이 샘플로는 닿지 않는다.

## 3. 측정 설계

- 입력(STEP 1·3 파일)은 하나로 고정하고 STEP 4만 구성을 바꿔 실행한다(`bench/bench_step4.sbatch`, 제출은 `bench/submit_ladder.sh`).
- `S:T` = 단일 프로세스, OpenMP T스레드(기존 `run_step.py 4`). `S:1`이 번들의 기존 실행 조건이다. `M:R:T` = MPI R rank × rank당 T스레드(`run_step.py 4 --mpi`). 배치 k는 rank k % R이 푼다.
- 설정: `num_batches=64`(64 rank까지 모두 일하도록), `samples_per_batch=50000`, D=10⁶은 `max_iterations=3`, D=10⁷은 `max_iterations=1`(시간 제약).
- 1노드(kqsvr05, 2×16코어, `--hint=nomultithread`)를 독점하고 구성을 무작위 순서로 실행. 2노드 구성(64 rank)은 별도 작업. 세 노드 중 하나는 항상 비워 qc-cloud 카나리 자리를 둔다.

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| S:1 | 1 | 1 | 57,753 (16.0 h) | 57,730 | 22 | 1.00× | — |
| S:32 | 1 | 32 | 3,481 | 3,459 | 22 | 16.6× | 1.00× |
| M:4:8 | 1 | 32 | 2,652 | 2,630 | 22 | 21.8× | 1.31× |
| M:8:4 | 1 | 32 | 2,574 | 2,552 | 22 | 22.4× | 1.35× |
| M:16:2 | 1 | 32 | 2,530 | 2,507 | 24 | 22.8× | 1.38× |
| M:32:1 | 1 | 32 | 2,503 | 2,475 | 28 | 23.1× | 1.39× |
| M:64:1 | 2 | 64 | (3279 대기) | | | | |

- 여섯 구성의 에너지가 모두 −7.928977 Ha로 같다(동등성 검사 6건 통과, 1스레드끼리는 비트 동일). FCI 대비 +132 mHa인 것은 D=10⁶이 FCI 공간의 0.6%뿐이기 때문이며 측정 목적과는 무관하다.
- **대각화가 전체의 99.9%** 이고 rank 0만 하는 나머지(구성 복구·결과 처리)는 22초라, MPI로 나눌 수 없는 직렬 부분은 사실상 없다.
- 같은 32코어에서 스레드만 쓰면 16.6배, 배치 병렬이면 21.8~23.1배. rank를 4→32로 늘려도 1.31→1.39배로 완만하게 좋아진다. 한 노드 안에서는 코어 수가 상한이고, 스레드 대 프로세스의 차이가 이득의 대부분이다.

## 6. 왜 H₁₆는 N₂보다 표 하나에 10배 오래 걸리나

같은 D=10⁶에서 N₂(이전 측정)는 표 하나에 1코어 50초, H₁₆는 300초다. 두 문제의 첫 배치를 똑같이 만들어 32스레드로 비교했다(`davidson_diag.py`, 작업 3282).

| 항목 | N₂ (5+5 전자) | H₁₆ (8+8 전자) | 비 |
| --- | ---: | ---: | ---: |
| Davidson 반복 수 (수렴까지) | 7 | 21 | 3.0× |
| H·c 1회, 표 칸당 시간 | 2.0×10⁻⁷ s | 6.0×10⁻⁷ s | 3.0× |
| 표 하나 풀이 (32스레드) | 2.0 s (D=3.5×10⁵) | 18.4 s (D=10⁶) | 칸당 3.2× |

반복 수 3배(강상관이라 바닥 상태가 여러 문자열에 퍼져 천천히 수렴)와 반복당 비용 3배(전자가 많아 칸당 연결 수가 많고, 반 채움 분포는 연결된 칸이 실제로 표 안에 있을 확률이 높음)가 곱해진 결과다.

참고로 전체 공간 1.66×10⁸의 FCI는 32코어 22분인데, 그 0.6%인 10⁶ 표 하나가 32코어 18초다. 칸당으로 보면 FCI가 100배 이상 효율적이다. FCI는 "모든 조합이 있다"는 규칙성을 벡터 연산으로 쓰지만 SQD의 표는 불규칙한 선택 조합이라 칸마다 이웃을 조회해야 한다(선택 CI 커널의 본질적 한계).

## 7. 스레드 병렬과 배치 병렬의 차이

- **스레드(S:T)**: 프로세스 1개가 64개 표를 차례로 푼다. 표 하나의 행렬·벡터 곱만 T스레드가 나눈다. 코드는 바꾸지 않고 `OMP_NUM_THREADS`만 정한다. 32스레드에서 16.6배로, 직교화·작은 고유값 문제·파이썬 제어 같은 직렬 부분과 메모리 대역폭이 한계다.
- **배치 병렬(M:R:T)**: R개 프로세스가 표를 나눠 갖고 각자 T스레드로 푼다. 푸는 동안 통신이 없다. 코드는 원문의 `sci_solver`를 감싸는 함수 하나(`sqd_workflow/mpi_solver.py`의 `batch_parallel`)와 rank 0 전용 입출력뿐이다. 조건은 배치 수 ≥ rank 수, rank당 메모리(D=10⁷에서 약 3 GB, 10⁸에서 30 GB).

## 8. 재현

```bash
# STEP 1~3 (1노드, FCI 포함 약 25분)
slurm/submit_scaled.sh -p h16_sto6g_32q -s ffsim -K -W kqsvr04
# STEP 4 사다리 (RUN = 위 run 폴더, B = 공유 bench 폴더)
bench/submit_ladder.sh -r $RUN -B $B -k h16_d1e6 "num_batches=64;samples_per_batch=50000;max_dim=1000;max_iterations=3" \
    -C "S:1 S:32 M:4:8 M:8:4 M:16:2 M:32:1" -w kqsvr05 -T 24:00:00
bench/submit_ladder.sh -r $RUN -B $B -k h16_d1e7 "num_batches=64;samples_per_batch=50000;max_dim=3162;max_iterations=1" \
    -C "S:32 M:8:4 M:16:2 M:32:1" -w kqsvr05 -T 12:00:00 -d <앞 작업>
bench/submit_ladder.sh -r $RUN -B $B -k h16_d1e6 "…" -C "M:64:1" -N 2 -d <앞 작업>
python bench/summarize.py $B --out <쓰기 가능한 폴더>
```
